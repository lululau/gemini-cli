# 包间通信机制

## 概述

Gemini
CLI 的 CLI 包和 Core 包通过严格定义的接口和异步消息传递进行通信。这种设计确保了两个包的解耦，使得各自可以独立开发和测试。

## 通信架构

```
CLI 包 (packages/cli)
    ├─ UI 层 (AppContainer)
    │   ├─ 接收用户输入
    │   ├─ 管理 UI 状态
    │   └─ 显示响应
    │
    ├─ Config 创建
    │   └─ 从 Settings 创建 Config 对象
    │
    └─ Core 包 API 调用
           │
           ▼
Core 包 (packages/core)
    ├─ Config 类
    │   ├─ 初始化工具
    │   ├─ 配置认证
    │   └─ 管理会话
    │
    ├─ GeminiClient
    │   ├─ 管理对话
    │   ├─ 调用 API
    │   └─ 处理流
    │
    └─ ToolRegistry
           ├─ 注册工具
           ├─ 调度工具
           └─ 返回结果
```

## Config 对象

Config 对象是 CLI 和 Core 之间的主要通信枢纽。

### Config 创建流程

```typescript
// packages/cli/src/config/config.ts 中
export async function loadCliConfig(
  settings: Settings,
  allExtensions: GeminiCLIExtension[],
  sessionId: string,
  argv: CliArgs,
  cwd: string = process.cwd(),
): Promise<Config> {
  // 从 Settings 提取配置参数
  const configParams: ConfigParameters = {
    sessionId,
    model: settings.merged.models?.default || DEFAULT_GEMINI_MODEL,
    debugMode: argv.debug || false,
    targetDir: cwd,
    // ... 更多参数
  };

  // 创建 Config 实例
  const config = new Config(configParams);

  // 初始化 Config（加载工具、MCP等）
  await config.initialize();

  return config;
}
```

### Config 接口示例

```typescript
// packages/core/src/config/config.ts 中
export class Config {
```

## 异步通信流程

### 交互式模式通信

```
CLI 用户输入
    ↓
AppContainer 处理 onInput
    ↓
构造 Message 对象
    ↓
调用 config.getGeminiClient().sendMessageStream()
    │
    ├─ GeminiClient 返回 AsyncGenerator<ServerGeminiStreamEvent>
    │
    ├─ 事件类型：
    │   ├─ content (文本)
    │   ├─ toolCall (工具调用)
    │   ├─ thought (思维)
    │   └─ error (错误)
    │
    └─ CLI 订阅事件流
       └─ 实时更新 UI
```

### 代码示例

```typescript
// packages/cli 中
const messageStream = await config
  .getGeminiClient()
  .sendMessageStream(messageContent, signal, prompt_id);

for await (const event of messageStream) {
  switch (event.type) {
    case 'content':
      // 更新 UI 显示文本
      updateUIWithContent(event.value);
      break;
    case 'toolCall':
      // 显示工具调用确认
      showToolConfirmation(event);
      break;
    case 'thought':
      // 显示思维过程
      updateThoughtDisplay(event.value);
      break;
    case 'error':
      // 处理错误
      handleError(event.error);
      break;
  }
}
```

## 工具确认通信

### MessageBus 机制

```
工具执行请求
    ↓
MessageBus.publish(ToolConfirmationRequest)
    ↓
PolicyEngine 检查权限
    ├─ ALLOW → 自动确认
    ├─ DENY → 拒绝请求
    └─ ASK_USER → 等待 UI 响应
    ↓
UI 显示确认对话
    ↓
用户做出选择
    ↓
CLI 发送 ToolConfirmationResponse
    ↓
MessageBus 处理响应
    ↓
工具执行或拒绝
```

### MessageBus 接口

```typescript
// packages/core/src/confirmation-bus/message-bus.ts
export class MessageBus extends EventEmitter {
  publish(message: Message): void;
  subscribe<T extends Message>(
    type: T['type'],
    listener: (message: T) => void,
  ): void;
  unsubscribe(type: string, listener: (message: any) => void): void;
}

// 消息类型
type Message =
  | ToolConfirmationRequest
  | ToolConfirmationResponse
  | ToolPolicyRejection;
```

## 工具系统通信

### ToolRegistry 接口

```typescript
// 工具查询
const tool = toolRegistry.getTool(toolName);

// 工具列表
const tools = toolRegistry.getAllTools();

// 工具执行
const invocation = tool.build(params);
const result = await invocation.execute(signal);
```

### 工具执行流程

```
CLI 接收 LLM 工具调用
    ↓
调用 CoreToolScheduler.schedule()
    ↓
ToolRegistry 查找工具
    ↓
构造 ToolInvocation
    ↓
检查是否需要确认
    ├─ 需要 → 通过 MessageBus 请求 UI 确认
    └─ 不需要 → 直接执行
    ↓
执行工具 (tool.execute())
    ├─ 文件操作
    ├─ Shell 命令
    ├─ Web API 调用
    └─ ...
    ↓
收集结果
    ↓
转换为 LLM 可理解的格式
    ↓
返回给 GeminiClient
```

## 会话状态管理

### 状态同步

```
创建会话
    ↓
Config 生成 sessionId
    ↓
GeminiClient 使用 sessionId
    ↓
CLI 在 AppContainer 中保存会话
    ↓
Core 维护会话历史
    ↓
结束会话时清理资源
```

## 错误通信

### 错误处理流程

```
Core 生成错误
    ↓
包装为 FatalError
    ↓
传递给 CLI
    ↓
CLI 错误处理程序
    ├─ 捕获错误
    ├─ 格式化错误消息
    ├─ 显示在 UI
    └─ 记录日志
```

## 总结

CLI 和 Core 包通过 Config 对象、异步消息流、MessageBus 和精心设计的接口进行通信。这种设计既保证了解耦性，又提供了完整的功能集成。
