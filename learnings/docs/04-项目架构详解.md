# 项目架构详解

## 架构设计原则

Gemini CLI 的架构设计遵循以下原则：

1. **关注点分离（Separation of Concerns）** - 不同层次和模块各司其职
2. **高内聚低耦合** - 模块内部紧密，模块间松散
3. **可扩展性** - 便于添加新功能和工具
4. **类型安全** - 充分利用 TypeScript 的类型系统
5. **可测试性** - 每个模块都可独立测试

## 数据流

### 交互式模式数据流

```
用户输入
  ↓
AppContainer 捕获
  ↓
onInput 事件处理
  ↓
构造用户消息
  ↓
调用 GeminiClient.sendMessageStream()
  ↓
流式接收 Agent 响应
  ├─ 文本内容 → 展示在 UI
  ├─ 工具调用 → ToolCallDisplay
  ├─ 思维过程 → 思维展示
  └─ 错误 → 错误处理
  ↓
GeminiChat 维护历史记录
  ↓
UI 更新反映新状态
```

### Turn 处理流

```
Turn.run()
    ├─ 1. 调用 GeminiChat.sendMessageStream()
    │      ↓
    │   调用 Gemini API
    │      ↓
    │   处理流式响应
    │
    ├─ 2. 生成 ServerGeminiStreamEvent
    │      ├─ Thought (思维)
    │      ├─ Content (文本)
    │      ├─ ToolCall (工具调用)
    │      └─ Error (错误)
    │
    ├─ 3. UI 订阅事件流
    │      └─ 实时更新展示
    │
    └─ 4. 处理工具调用
           ├─ 工具调度
           ├─ 参数验证
           ├─ 用户确认
           ├─ 执行工具
           └─ 收集结果
```

## 工具系统架构

### 工具执行流程

```
LLM 请求工具调用
    ↓
CoreToolScheduler._schedule()
    ├─ 验证工具存在
    ├─ 验证参数
    ├─ 通过 PolicyEngine 检查权限
    │  ├─ ALLOW → 直接执行
    │  ├─ DENY → 返回拒绝
    │  └─ ASK_USER → 询问用户
    ├─ 等待用户确认（如需要）
    ├─ 执行 tool.buildAndExecute()
    └─ 收集结果
    ↓
将结果转换为新的用户消息
    ↓
继续 Agent 循环
```

```

    ├─ 从 Settings 初始化
    ├─ 从 CLI 参数覆盖
    ├─ 从 GEMINI.md 加载项目配置
    └─ 运行时动态更新
         ↓
各子系统使用 Config
    ├─ GeminiClient
    ├─ ToolRegistry
    ├─ UI Components
    └─ ... (其他)
```

## 认证架构

```
认证初始化流程
    ↓
选择认证方式
    ├─ OAuth (推荐)
    ├─ API Key
    └─ Vertex AI
    ↓
获取凭证
    ├─ 保存到本地

    ↓

    ├─ 配置认证信息
    ├─ 初始化 API 客户端
    └─ 准备发送请求
```

## 扩展系统架构

```
扩展加载流程
    ↓
Extension 发现
    ├─ 从 npm_modules 扫描
    ├─ 读取 package.json
    └─ 验证扩展定义
    ↓
Extension 注册
    ├─ 注册工具（通过 ToolRegistry）
    ├─ 注册命令
    ├─ 注册 MCP 服务器
    └─ 初始化扩展
    ↓
扩展启用/禁用
    ├─ 通过 ExtensionEnablementManager 管理
    ├─ 用户配置持久化
    └─ UI 中显示
```

## MCP 集成架构

```
MCP Server 配置 (config.ts)
    ├─ 命令行 stdio
    ├─ HTTP 远程
    └─ WebSocket
    ↓
MCP 客户端连接
    ├─ 创建传输层
    ├─ 建立连接
    └─ 初始化握手
    ↓
工具发现
    ├─ 调用 tools/list
    ├─ 过滤和验证
    └─ 包装为 DiscoveredMCPTool
    ↓
注册到 ToolRegistry
    ├─ 生成唯一名称
    ├─ 添加前缀以避免冲突
    └─ 支持工具别名
```

## 持久化架构

```
会话管理
    ├─ 会话创建 → 保存会话 ID
    ├─ 会话活动 → 记录活动时间
    └─ 会话清理 → 删除过期会话
    ↓
检查点管理
    ├─ 周期性保存检查点
    ├─ 压缩历史记录
    └─ 支持恢复
    ↓
记忆系统
    ├─ GEMINI.md 文件
    ├─ 支持多个记忆文件
    └─ 跨会话持久化
```

## 类型系统

### 核心类型定义

```typescript
// 配置
interface ConfigParameters {
  sessionId: string;
  model: string;
  debugMode: boolean;
  // ... 更多配置
}

// 工具
interface DeclarativeTool<TParams, TResult> {
  name: string;
  validate(params: TParams): string | null;
  build(params: TParams): ToolInvocation<TParams, TResult>;
}

// 消息
interface Content {
  role: 'user' | 'model';
  parts: Part[];
}

// Turn 事件
type ServerGeminiStreamEvent =
  | { type: 'content'; value: string }
  | { type: 'toolCall'; name: string; args: unknown }
  | { type: 'thought'; value: string }
  | { type: 'error'; error: Error };
```

## 性能考虑

### 流式处理优化

- 使用异步生成器流式输出
- 避免等待完整响应
- 实时反馈给用户

### 缓存策略

- 工具元数据缓存
- 会话历史缓存
- IDE 上下文缓存

### 资源管理

- 连接复用
- 内存管理
- Token 限制处理

## 总结

Gemini
CLI 的架构通过清晰的分层、模块化的设计和完善的接口定义，实现了一个高度可扩展、易于维护的 AI
Agent 系统。每一层都有明确的职责，使得系统易于理解、测试和扩展。
