# AI Agent 基础概念

## 概述

AI
Agent 是一种能够感知环境、做出决策并采取行动来实现特定目标的智能系统。与传统的被动应用程序不同，Agent 具有自主性、反应性和目标导向性。Gemini
CLI 通过将 Google 的 Gemini
LLM（大语言模型）与工具调用机制相结合，实现了一个实用的 AI Agent 系统。

## 核心特征

### 1. 自主性（Autonomy）

Agent 能够在没有人类干预的情况下做出决策和执行操作。虽然某些操作（如文件写入、命令执行）可能需要用户确认，但 Agent 能够自主规划和执行任务序列。

### 2. 反应性（Reactivity）

Agent 能够感知环境变化并做出相应的反应。在 Gemini CLI 中，这表现为：

- 读取文件系统状态
- 执行 Shell 命令并获得输出
- 调用 Web API 并处理响应

### 3. 目标导向性（Goal-Oriented）

Agent 为特定目标而工作，并能够通过多步骤的操作序列来实现这些目标。

### 4. 交互性（Interactivity）

Agent 能够与用户进行交互，获取反馈、寻求确认或澄清意图。

## AI Agent vs 传统程序

| 特性         | 传统程序         | AI Agent             |
| ------------ | ---------------- | -------------------- |
| **控制流**   | 明确的指令序列   | 由模型动态决定       |
| **适应性**   | 固定逻辑         | 根据输入灵活调整     |
| **错误处理** | 预定义的异常处理 | 模型推理恢复         |
| **学习能力** | 不学习           | 每次交互都基于上下文 |
| **用户交互** | 结构化输入/输出  | 自然语言交互         |

## Agentic Loop（智能体循环）

Agentic Loop 是 AI Agent 运作的核心机制，描述了 Agent 如何在循环中迭代执行任务：

```
每个 Turn（轮次）流程：

1. 用户提供输入或之前的工具执行结果
   ↓
2. 构造 Prompt（包含可用工具列表和历史记录）
   ↓
3. 调用 LLM（Gemini API）
   ↓
4. LLM 返回响应：
   - 可能包含工具调用请求
   - 可能包含文本内容
   - 可能包含思维过程
   ↓
5. 解析 LLM 响应
   ├─ 如果有工具调用 → 执行工具（步骤6）
   └─ 如果无工具调用 → 输出最终响应（步骤8）
   ↓
6. 执行工具
   ├─ 验证参数
   ├─ 获取用户确认（如需要）
   ├─ 执行工具逻辑
   └─ 收集结果
   ↓
7. 将工具结果转换为新的用户消息
   ↓
8. 返回步骤2，继续下一个 Turn
   （直到 LLM 不再请求工具调用）
   ↓
9. 返回最终响应给用户
```

## 工具系统（Tools）

工具是 Agent 与外界交互的桥梁。Gemini CLI 提供了多种内置工具：

### 文件操作工具

- **ReadFileTool**: 读取文件内容
- **WriteFileTool**: 写入或创建文件
- **EditTool**: 编辑现有文件的特定部分

### 代码搜索工具

- **RipGrepTool**: 快速文本搜索
- **GrepTool**: 正则表达式搜索
- **GlobTool**: 通配符文件查找

### 系统交互工具

- **ShellTool**: 执行 Shell 命令
- **LSTool**: 列出目录内容

### 信息获取工具

- **WebFetchTool**: 获取网页内容
- **WebSearchTool**: 执行 Web 搜索

### 上下文工具

- **MemoryTool**: 管理持久化记忆

## 上下文和记忆

### 对话历史（Conversation History）

Agent 维护完整的对话历史，包括：

- 用户消息
- 工具调用请求
- 工具执行结果
- Agent 响应

### 工作区上下文（Workspace Context）

Agent 理解当前工作区的结构：

- 项目文件
- 代码库结构
- 配置文件
- GEMINI.md 文件（项目指导）

### 持久化记忆（Persistent Memory）

- 通过 GEMINI.md 文件存储长期信息
- 支持多个内存文件
- 在会话间保持

## 确认和安全

由于 Agent 可能执行危险操作（如删除文件、运行命令），系统包含多层确认机制：

```
工具执行流程：
┌─────────────────────┐
│  LLM 请求工具调用    │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│  验证工具参数       │
│  参数有效？         │
└──────────┬──────────┘
           │
      ┌────┴────┐
      │          │
    否│          │是
      │          │
      ▼          ▼
  返回错误   ┌─────────────────┐
            │ 政策检查        │
            │ (PolicyEngine)  │
            └────────┬────────┘
                     │
         ┌───────────┼───────────┐
         │           │           │
       允许        拒绝        询问用户
         │           │           │
         ▼           ▼           ▼
       执行      返回拒绝   等待用户确认
       工具      错误消息
         │
         ▼
    返回工具结果
```

## AI Agent 的应用场景

1. **代码生成和编辑** - 自动编写、修改和优化代码
2. **文件和信息整理** - 整理项目结构、提取信息
3. **问题诊断** - 分析错误日志、寻找问题根因
4. **研究和学习** - 获取信息、总结知识
5. **自动化任务** - 执行重复的开发工作流

## Gemini CLI 中的 Agent 实现

Gemini CLI 实现了一个以下特点的 AI Agent：

1. **多模态输入**: 支持文本、代码、文件系统内容
2. **流式处理**: 实时流式输出模型响应和工具执行进度
3. **交互式确认**: 在执行危险操作前寻求用户批准
4. **上下文压缩**: 在超过 Token 限制时自动压缩历史记录
5. **扩展性**: 通过 MCP（Model Context Protocol）支持自定义工具
6. **IDE 集成**: 与 VS Code 等 IDE 集成，获取代码上下文

## 关键概念术语表

| 术语                | 定义                                                          |
| ------------------- | ------------------------------------------------------------- |
| **Turn**            | Agent 循环中的一个完整迭代，从用户输入到最终响应              |
| **Tool Call**       | LLM 请求 Agent 执行特定工具的操作                             |
| **Tool Invocation** | Tool Call 的实际执行过程                                      |
| **Prompt**          | 发送给 LLM 的完整输入，包括系统指令、工具定义、历史和用户输入 |
| **Context Window**  | LLM 一次能处理的最大 Token 数量                               |
| **Token**           | 文本的最小单位（通常一个词的一部分到几个词）                  |
| **Streaming**       | 实时流式接收 LLM 输出，而不是等待完整响应                     |

## 总结

AI
Agent 是现代 AI 应用的核心范式，通过结合 LLM 的推理能力和工具调用机制，创造出能够解决真实世界问题的智能系统。Gemini
CLI 展示了如何在开发环境中实现这种范式，为开发者提供强大的 AI 助手。
